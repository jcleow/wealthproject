Multiyear Financial Planning (status: todo)

Background / Context
- Problem: Home page Financial Data lacks a time dimension; users can’t reason about projected states across years. Need year selector and consistent projections.
- Requirement: Backend is the single source of truth; all projection/override computation must run server-side. Annual granularity for net worth.
- UX: Year dropdown/input (0–20) at Financial Data; net worth graph reflects edits. Non-annual inputs are normalized to annual for display and computation. Overrides should surface via markers on the graph and let users jump to that year’s data.

Questions Raised
- Growth assumptions source: static defaults vs user-editable config? (pending)
- Override semantics: latest-wins with revision? (proposed)
- API placement: projection and override application confirmed to live in backend.
- Graph behavior: annual series; markers for override presence; click-to-jump to selected year (confirmed).
- Frequency handling: normalize non-annual inputs to annual before projection/output (confirmed).

Scope
- Goal: support year-specific financial data editing (0–20), persist overrides, and recompute net worth annually on the backend only.
- Blocks frontend: Year selector + override markers + net worth sync (new frontend work, status: todo).
- New items added via year edits persist forward: a line created at year N becomes part of the base for N and all downstream years (N+1…20), and is subject to growth and future overrides.
- Default growth profile: balanced assumptions with bounds to avoid extremes; growth editable via API.

Assumptions
- Backend is the single source of truth for projections and override application.
- Annual granularity for projections and net worth graph.
- Non-annual user inputs must be normalized to annual amounts before projection/output.
- Growth assumptions are global; overrides at year N replace projected values for that year and influence downstream years.
- Growth config is user-editable; apply logical defaults (balanced profile) with bounds to prevent extreme inputs.

Data Model (backend, status: todo)
- Year 0 snapshot: persisted assets, liabilities, income, expenses as current state (reuse existing entities).
- Growth config: global annual growth/decay assumptions per category, user-editable via API. Seed with balanced defaults and enforce bounds (e.g., -50% to +50%). Suggested defaults (annual_rate_pct):
  - asset_cash: +1.5%
  - asset_equity: +6.0%
  - asset_property: +3.0%
  - liability_debt: -3.0% (decay)
  - income: +3.0%
  - expense: +2.0%
- Overrides table: user/session + year + item (id/type/category) + value + frequency + metadata (override reason, timestamps, revision). Needed to flag override presence per year for graph markers. Keep only the latest applied override per item/year.
- New items created via overrides: assign stable IDs, categorize (asset/liability/income/expense), persist from year N forward as part of the projection base.
- Suggested schema additions (Postgres):
  - growth_configs: id (pk), category (enum: asset_cash, asset_equity, asset_property, liability_debt, income, expense), annual_rate_pct (numeric), lower_bound_pct, upper_bound_pct, updated_at.
  - financial_overrides: id (pk), year (int), item_id (uuid), item_type (enum: asset|liability|income|expense), category (text or enum aligning to existing chart of accounts), amount (numeric), frequency (enum: annual|monthly|weekly|biweekly|quarterly|semiannual), applied_at (timestamp), revision (int), source_frequency (optional), source_amount (optional). Latest applied wins per item/year.
  - items_catalog (if not present): id (uuid pk), name, item_type (enum), category, base_amount (numeric annualized), frequency_at_creation (enum), created_year (int, default 0). New items created at year N get created_year=N to guide projection starting point.

Projection Engine (backend, status: todo)
- Inputs: year 0 snapshot, growth config, overrides by year.
- Frequency normalization (annualization):
  - annual: 1x, monthly: *12, weekly: *52, biweekly: *26, quarterly: *4, semiannual: *2. All displayed numbers are annualized; also store source frequency/amount for UI labeling.
- Steps:
  1) Normalize year 0 snapshot to annual amounts using frequency rules.
  2) Seed projection base with year 0 items (plus any items whose created_year <=0).
  3) For each year Y from 0..20:
     - Apply growth per item using category-specific rate from growth config (bounded).
     - Apply overrides for year Y (latest-wins per item/year); if override introduces a new item, add it to projection base with created_year=Y and start applying growth from Y forward.
     - After overrides, compute balance sheet (assets/liabilities), P&L (income/expenses), net cash, net worth.
     - Mark hasOverrides=true if any override exists for year Y.
  4) After processing overrides at Y, the updated state becomes the base for Y+1 projection.
  5) Return the full timeline with annualized amounts and metadata (hasOverrides, growth inputs used, source frequency if different).
- Output shape per year: assets, liabilities, income, expenses (annualized), net cash/NW, hasOverrides bool, growth inputs used.

APIs (backend, status: todo)
- GET /api/v1/financial/timeline: return years 0–20 with projected balance sheet, P&L, net worth series, and override flags.
- PUT /api/v1/financial/timeline/{year}: upsert edits for that year (amount + frequency + item refs or new items), store overrides (latest-wins per item/year), rerun projection, return refreshed timeline. New items created at year N persist forward and receive growth/overrides downstream.
  - Request body (example):
    - year: int
    - edits: array of { itemId?: uuid, name?: string, itemType: asset|liability|income|expense, category: string, amount: number, frequency: annual|monthly|weekly|biweekly|quarterly|semiannual }
    - note: optional
  - Response: full timeline array years 0–20 with annualized amounts, hasOverrides, and source frequency/amount metadata for UI labels.
- (Optional) GET/PUT /api/v1/financial/growth: manage global growth assumptions with bounded inputs.
  - Payload: list of { category, annual_rate_pct, lower_bound_pct, upper_bound_pct }
- Versioned responses; responses should echo annualized values and override markers.

Frontend Integration Notes (status: todo)
- Shared year selector (0–20) near Financial Data header; uses GET timeline.
- Editing year N uses PUT timeline/{year}; updates Financial Data cards and net worth graph from returned timeline.
- Graph displays annual series; show a small blue triangle under x-axis for years where hasOverrides=true; clicking jumps to that year’s Financial Data.
- All displayed amounts are annualized; show sublabels/tooltips indicating the source frequency when different (e.g., “$24,000 annualized from $2,000 monthly” in cards, and tag “annualized” in graph tooltips).
 - When a new item is added in year N, surface it in lists/tables for year N and all downstream years; indicate creation year in detail tooltip if helpful.

Risks / Decisions
- Growth config source (static vs editable) needs confirmation.
- Conflict resolution: multiple overrides for same item/year use latest-applied wins; revisions optional.
- Performance: projection should be deterministic and fast; consider caching per session/user with invalidation on overrides.
